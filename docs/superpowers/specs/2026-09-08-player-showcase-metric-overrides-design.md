# 打手风采展示指标覆盖设计

日期：2026-09-08

## 目标

允许管理员单独调整打手风采中的评分、完成单和完成率，用于冷启动或线下业绩补录；不修改其他页面使用的真实数据，也不影响评价、订单统计、派单与接单资格判断。

## 数据模型

在 `player_showcase` 增加三个可空字段：

- `display_rating decimal(3,2) NULL`：范围 1.00～5.00。
- `display_completed_orders int NULL`：大于等于 0。
- `display_complete_rate decimal(5,2) NULL`：范围 0.00～100.00。

`NULL` 表示使用真实值；有值表示仅覆盖风采公开接口的展示值。

## 数据流

风采公开列表和详情仍返回既有字段：

- `avgRating`
- `completedOrders`
- `completeRate`

服务端优先返回 `player_showcase` 中的展示值；展示值为空时回退到原有真实值。小程序无需区分数据来源。

管理后台风采列表返回：

- 当前真实值
- 当前展示覆盖值

运营可分别填写或清空三个展示值。清空后立即恢复为真实值。

## 约束

- 在线、满载、当前占用和是否可指定必须保持实时真实数据，不提供覆盖能力。
- 展示评分限制为 1.00～5.00。
- 展示完成单限制为非负整数。
- 展示完成率限制为 0.00～100.00。
- 非法值由后端拒绝，不能只依赖前端校验。
- 保存风采卡继续记录现有操作日志。

## 后台交互

在新增/编辑风采弹窗增加“风采展示数据”区域：

- 每项显示真实值。
- 输入框为空时提示“留空使用真实值”。
- 编辑时可清空覆盖值。
- 当前公开展示结果可直接预览。

## 兼容性

- 新字段均可空，已有风采卡默认继续展示真实数据。
- 公共接口字段名不变。
- 不修改 `player.avg_rating`、`player.complete_rate`、`player.order_count`。
- 不修改订单表和评价表。

## 验收

1. 未填写覆盖值时，风采页展示真实值。
2. 填写任意一项后，仅该项在风采首页、列表和详情被覆盖。
3. 打手管理详情和其他业务页面仍显示真实值。
4. 清空覆盖值后恢复真实值。
5. 边界值可保存，越界值被前后端阻止。
6. 已有风采卡在数据库迁移后行为不变。
